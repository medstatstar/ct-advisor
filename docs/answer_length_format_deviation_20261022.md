# ct-advisor 回答「长度 / 格式」与用户需求的偏差核查

**日期**：2026-10-22 · **数据源**：`ct-update/_reports/feishu_log_fetch_20261021_203034.json`（advisorlog 近 30 天 68 条真实问答）+ `adapters/coze` 引擎作答契约（`shared_contract.md` / `answer_postprocess.py` / `coze-output-guidelines-*.md`）
**目的**：在上一轮"扩大适用范围 + 文档做实"之后，专门核一遍**回答长度、输出格式**两维与真实用户需求之间的偏差，并给出可落地的修正建议。

---

## 0 结论先行（三句话）

1. **长度**：引擎契约把 complex 硬钉在 **≤1000 字**，但 68 条历史真实回答中位数 **1553 字**、56% 超 1500 字——要么该上限未上线、要么被长问题冲破；而重度用户（CRO/药企 PM）明确要"制度全文 / 方案全文 / RWS 方案"，**≤1000 字根本装不下**，与"要成文、不要提纲"的明确诉求正面对冲。
2. **格式**：工作台 UI 给了 5 个 `output_format` 选项（auto/doc/outline/table/ppt），但**引擎契约里没有任何一条处理 doc/outline/table/ppt**——SKILL.md 自己写的是"engine honours if able"（尽力而为 = 基本不生效）。**5 个选项里引擎实际只认 `auto` 一种**，其余 4 个是装饰。
3. **引用溯源**：反而做得好——84% 的真实回答含来源/出处/指南/法规/DOI 类词，32% 用户明确要求可核查来源的需求已被契约覆盖，**这不是偏差点**。

## 3 偏差矩阵：需求 vs 现状

| 用户真实需求（来自 68 条 + §6 节选 + P2-3） | 占比/证据 | 引擎现状 | 偏差 |
|---|---|---|---|
| **简短直答**（是非/单点规则） | simple 段（少量） | simple≤200 硬上限 | ✅ 基本对齐 |
| **成文 / 全文**（"互联网医院机构/财务制度全文，要成文不要提纲"；RWS 方案；器械方案审核） | 12% 显式要成文 + 重度用户主体诉求 | complex≤1000 硬截断 + "请追问" | ❌ **严重偏差**：1000 字装不下制度/方案全文 |
| **PPT 大纲** | 6% | 引擎无 PPT 模式 | ❌ 选项装饰，不生效 |
| **表格** | 4% | 支持 md 表格但仅 7% 回答用到 | ⚠️ 弱：用户要表格时未稳定产出 |
| **提纲**（报告大纲重构、RWS 方案/PPT 大纲） | 部分 | 默认即"先答后展"结构 | ✅ 对齐（但用户要"成文"时反而嫌太提纲） |
| **可核查来源/引用** | 32% 显式 | C-依据强制具体出处 | ✅ 对齐（84% 回答已含出处词） |
| **多轮深挖长任务**（重度用户单会话最长 5 轮） | 会话结构 | 截断逼出"请追问" + 我们已做上下文注入 | ⚠️ 双向：截断迫使分轮，上下文已补，但"一次性给全文"仍不可得 |

---

## 4 根因

- **长度天花板是"防过长"导向，未考虑"交付物撰写"导向**：v1.11 修的是"单点方法学问题返回多节长报告、原问题被稀释"（历史 simple 339 / complex 932 字无上限）。这一修把天花板压到 complex≤1000，但**没给"用户就是要一整篇制度/方案"开例外**——而上一轮分析刚确认"交付物撰写"是高频核心域（47%），恰恰是吃字数的场景。
- **`output_format` 是"补 UI 不补引擎"**：上一轮（Task 5）只在前端加了下拉框 + 透传 `query_meta.output_format`，但**引擎侧从未接这个字段**。本地 proxy 把它随 body 透传（可被未来 Coze 版本消费），当前版本等于空转。
- **本地短路路径未把 `output_format` 纳入缓存键**：用户先选 `auto` 得到缓存，再改选 `ppt` 会在 30 min 内拿到同一份 `auto` 答案（小瑕疵，但放大"格式选项无效"的观感）。

## 5 修正建议（按"是否触碰 Coze"分两档）

### 5.1 本地可做、零 Coze 改动、可逆（推荐先落地）

| ID | 改动 | 效果 | 落点 |
|---|---|---|---|
| **F1** | proxy 在 `output_format != "auto"` 时，把格式指令**注入 `original_question` 前缀/ `query_meta.format_hint`**（如"【请按 PPT 大纲输出：封面+每页要点】"），而非只透传 | 引擎读得到格式诉求，doc/outline/table/ppt 从"装饰"变"尽力生效" | `workbench/ct-advisor-proxy.py` `_inject_session` |
| **F2** | 缓存键加入 `output_format`：同问题不同格式不复用缓存 | 消除"选了 ppt 却拿到 auto 答案" | `scripts/session_store.py` `cache_get` 指纹 |
| **F3** | 长文档引导已做（P1-4 待办），但**把"要成文"识别为信号**：问题含"全文/成文/制度/方案/逐条/逐节"时，本地在 payload 提示引擎"这是交付物撰写，按完整篇幅作答、不要压成提纲" | 缓解"要成文却给提纲" | `scope_guard` 或 proxy 注入逻辑 |
| **F4** | SKILL.md 第 253 行把"engine honours if able"改为诚实表述："本地已透传 `output_format`；Coze 端自 vX 起消费，旧版退化为 auto" | 不误导维护者 | `SKILL.md` |

> 说明：F1–F3 只改**提示词/payload**，不改变引擎硬天花板——**仍无法突破 complex≤1000 的截断**。它们解决"格式选项有效化"，但解决不了"成文/全文被截断"。

### 5.2 需触碰 Coze（`adapters/coze`，须你明确授权）

| ID | 改动 | 效果 | 风险 |
|---|---|---|---|
| **F5** | `shared_contract` C3 增加：`output_format=doc` 时**解除/抬高长度天花板**（如 deliverable 型 ≤3000–5000 字），并新增 C-依据不变 | 真正交付"制度全文/方案全文" | 需重新部署 Coze 包；可能与"防过长"初衷冲突，须设上限防稀释 |
| **F6** | `answer_postprocess.py` 按 `query_meta.output_format` 分支截断（doc 用高 cap、table/outline/ppt 用结构约束而非字数约束） | 代码层与格式对齐 | 同上，需部署 |
| **F7** | `full_analysis_cfg.json` / `review_cfg.json` 顶部契约补 `output_format` 处理段 | 与配置同源 | 需部署 |

> 红线：F5–F7 改动 `adapters/coze/`，**未经你确认不落盘**（与之前"adapters/coze 零改动"口径一致，本次若要做需你点头）。
