# CSR — E3 Main Chain & Quality Gate (workflow G · 5.1-5.3)


## 5. CSR (workflow G)

> CSR **execution** is in `ref-ops-safety.md` §7; this section covers the E3 regulatory structure.

### 5.1 E3 main chain & consistency chain E3 main chain: `title & synopsis → ethics & organizational structure → objectives → study plan → subject disposition / deviations → efficacy → safety → discussion & conclusions → tables & figures → appendices`. Consistency chain: `final protocol / amendment → SAP & changes → data review & analysis-set decision → database version → TFL → CSR body / synopsis → appendices`. E3 Chinese & English are the same topic in different languages, not two independent evidence sources; translation ambiguity returns to the current official ICH original.

### 5.2 Results presentation & common distortions First state subject flow, exposure, data availability; primary analysis reports effect size, interval and necessary tests around the pre-specified estimand; secondary / exploratory / post-hoc clearly labeled; subgroup interpretation emphasizes consistency & interaction, not isolated single-subgroup significance; safety combines exposure / time / dose / severity / causality / discontinuation / death / clinical context; case narratives consistent with tables / line listings / database / safety reports; discussion answers what is supported, what is not, how limitations affect interpretation. Common distortions: writing only significant results or presenting non-significant as equivalent / no difference / no risk; not explaining missingness / intercurrent events / important deviations / analysis-set changes; inconsistent counts / version / date / endpoint / table caliber across the document; body exceeding what protocol / SAP / data support; missing or wrong-version appendices; transcribing TFL sentence-by-sentence without medical interpretation or benefit–risk judgment.

### 5.3 Submission-level quality gate Lock versions of protocol / SAP / database / TFL / body / synopsis / appendices; reconcile subject disposition / analysis set / deviations / exposure / efficacy / safety counts; estimand / main analysis / sensitivity / conclusion consistent; deaths / SAE / important AE / discontinuations / case narratives cross-consistent; important changes / limitations / data gaps honestly explained; table / figure / listing / appendix references / signatures / approvals meet delivery requirements. Missing key source → output only gap / risk / next quality gate, do not claim "submissible".

# CTD & M4 Series (workflow A/G)


## 7. CTD & M4 series (A / G)

| Module | Core content | Main basis |
|---|---|---|
| Module 1 | Regional admin / application form / prescription | Region-specific, not the unified CTD body |
| Module 2 | CTD preface, quality / non-clinical / clinical overview & summary | M4 / M4Q / M4S / M4E |
| Module 3 | Quality core data | M4Q and current Q-series / region |
| Module 4 | Non-clinical study reports | M4S and current S-series |
| Module 5 | Clinical study list, CSR & reports | M4E, E3 etc. |

M4E: 2.5 clinical overview (development strategy / evidence strength / limitations / benefit–risk / supports labeling, not result repetition); 2.7 clinical summary (more detailed cross-study summary & comparison); Module 5 holds study list / single CSR / pooled analysis / post-marketing / individual data. E3 CSR answers a single study, M4E 2.7 answers cross-study facts, M4E 2.5 answers whole-program regulatory interpretation & benefit–risk. M4Q / M4S do not push manufacturing / non-clinical issues into clinical argument. Granularity supports lifecycle replacement & version control; complete module numbering ≠ sufficient data — check evidence gaps & cross-module consistency; eCTD version / technical spec / regional validation rules verified against official implementation documents.

### 7.1 Submission dossier & eCTD filing preparation (workflow A / G) — assembly from CSR to submission
- **Scenario / Role**: Regulatory Affairs — assemble CSR, clinical overview/summary (§5.1 M4E 2.5/2.7), Module 5 etc. into a submission dossier and file by eCTD.
- **Correct handling path**: ① **Module organization**: Module 2 clinical overview/summary, Module 5 study list/CSR/pooled analysis (§7 M4); ② **eCTD**: Assemble per eCTD version/technical spec (§7); regional appendices (Module 1) satisfied separately; ③ **Consistency**: Submission dossier consistent with CSR (§5.3), SAP, database version; cross-module consistency (§8.1 dependency); ④ **Pre-filing check**: Versions/dates/numbers/signatures/attachments complete; gaps (§5.3 gap table) closed; ⑤ **Jurisdictional differences**: US-China/EU filing formats and gateways differ (§5.5 CMC, §8.3).
- **Key points**: Filing preparation is the "last mile" of consistency + format compliance — correct module organization, correct eCTD technical spec, cross-module consistency.
- ⚠️ eCTD version, technical spec and filing-gateway requirements are dynamic items — follow each country's eCTD implementation guide and current regulator website verbatim (officially verify).

# Approval Paths & Bridging (workflow B/C/registration · 5.4-5.8)


### 5.4 Conditional/accelerated approval evidence standards, MCID, biomarker subgroups & labeling balance (workflow B / C / registration)
When the primary endpoint is statistically significant but the effect size is below the MCID: **accelerated approval must be based on a surrogate endpoint or intermediate clinical endpoint (reasonably likely to predict clinical benefit)** — if it is a hard endpoint and effect size < MCID, AA generally does not apply; feasible paths are **enrichment of a biomarker-positive population for traditional approval**, or accelerated approval of that subgroup via surrogate. **AA evidence standard**: Must come from adequate and well-controlled trials providing "substantial evidence" on the surrogate, and **must commit to a post-marketing confirmatory trial (typically Phase 4) to verify clinical benefit** — this is a condition, not optional (China's conditional-approval logic is the same: single pivotal trial + surrogate + confirmatory commitment). **Biomarker subgroups**: If **preset and statistically robust** (interaction test) can support enrichment-label traditional approval; if post-hoc/exploratory, a separate confirmatory trial is required. **Labeling balance for "statistically significant but clinically uncertain"**: Honestly reflect whether effect size and CI cross clinical relevance, restrict the biomarker population, state the confirmatory commitment, and use restrictive indicative language ("demonstrated in biomarker-positive patients") + warnings to reduce off-label-use risk. FDA AA regulation (21 CFR 314.500), confirmatory-trial time limits, and China conditional-approval standards are dynamic items — follow the official text verbatim (officially verify).

### 5.5 US-China dual-filing bridging strategy (workflow registration / A)
When the same innovative drug is filed simultaneously in the US and China, the core differences and bridging: ① **CMC data mutual recognition**: Module 3 quality data are reviewed under different logics in the two countries; CTD/eCTD technical requirements and regional appendices (Module 1) are not mutually recognized and must be satisfied separately; ② **Ethnic sensitivity**: Per ICH E5, assess the bridging need for US→China (or reverse) extrapolation — if the China subpopulation proportion is sufficient and PK/PD and safety are consistent, bridging applies; if the proportion is insufficient or ethnic factors affect exposure/response, supplementary China data or a separate bridging trial is required; ③ **Clinical-data extrapolation**: In a global multicenter trial (MRCT), if the China subject proportion is insufficient, it generally **does not automatically waive** China bridging — must argue China population representativeness, whether statistical power is reached, and regulatory acceptability; ④ Design must satisfy both countries: unified master protocol + regional appendix + prior communication with both regulators (Pre-IND / Type B). CMC mutual-recognition scope, ethnic bridging and MRCT China-proportion requirements are dynamic items — follow current NMPA/FDA registration and bridging guidance (officially verify).

### 5.6 Regulatory validation of AI-assisted imaging endpoint read (workflow C / registration)
When submitting an NDA/BLA with AI algorithms assisting oncologic imaging assessment (e.g., iRECIST), must prove the AI read is **non-inferior to traditional BICR**: ① **Algorithm validation file**: Training/validation dataset composition, gold standard (typically BICR blinded independent central review) annotation, performance (sensitivity/specificity/agreement such as Kappa/ICC), bias assessment; ② **Explainability**: Must be able to show the read basis (heatmap/features), avoid black box; ③ **Reproducibility**: Consistent results across runs/versions/sites; version control and lock; ④ **Non-inferiority validation**: Preset AI vs BICR agreement boundary (e.g., difference within preset ±δ); main analysis uses BICR as reference; AI as supportive or replacement requires prior regulatory acceptance; ⑤ If AI replaces BICR, must be predefined in SAP/imaging charter and accepted by review. AI imaging validation and BICR-replacement acceptance criteria are dynamic items — follow current FDA/CDE imaging-endpoint and AI/ML software clinical-validation guidelines (officially verify).

### 5.7 Biosimilar immunogenicity differences & similarity determination (workflow C / registration)
In a biosimilar Phase 3 equivalence trial, an ADA positivity-rate difference (e.g., 16% vs reference 9%, p<0.05) **does not automatically negate Similarity**: ① Similarity is based on the **overall evidence chain** (analytical similarity, PK, PD, efficacy primary endpoint, safety primary endpoint all reaching equivalence) — if the primary endpoint is equivalent and only immunogenicity (secondary/exploratory) shows a statistical difference, similarity is generally not overturned; ② **Clinical-relevance assessment**: Must analyze whether ADA is accompanied by clinical consequences (neutralizing antibodies, loss of efficacy, severe allergy/infusion reaction), timing, persistence and titer; ③ **Supplementary analyses (required for BLA)**: Immunogenicity bridging (assay-consistency methods, positive control), correlation of ADA with efficacy/safety, risk minimization; ④ Regulators focus on "whether the difference is clinically meaningful" rather than mere statistical significance. Similarity determination and immunogenicity-bridging requirements are dynamic items — follow current biosimilar technical guidance and regulator text (officially verify).

### 5.8 Gene-therapy germline risk & subjects of childbearing potential management (workflow F / registration)
Gene-therapy vectors (AAV etc.) carry potential germline integration/vertical-transmission risk; for subjects of childbearing potential: ① **Contraception duration**: Based on **vector shedding kinetics** (duration of detectable vector DNA in blood/body fluids) and reproductive-toxicology studies comprehensively, not merely the dosing cycle; must be preset in ICF/contraception plan and cover the shedding window; ② **Unintended pregnancy handling**: Beyond routine pregnancy reporting (see `ref-ops-safety.md` §5.4), if the vector carries germline risk, must initiate **special molecular testing** (e.g., maternal/fetal sample vector-DNA testing) and **long-term offspring follow-up**, included in a dedicated safety monitoring program; ③ Subject education, contraception-adherence monitoring and no-pregnancy-during-shedding must be written into protocol and ICF. Contraception duration, vector testing and offspring-follow-up requirements are dynamic items — follow current gene-therapy non-clinical/clinical safety guidance (officially verify).

# Design & Endpoint Topics (workflow C/registration · 5.9-5.15)


### 5.9 Basket / umbrella Master Protocol design & multiplicity (workflow B / C)
Basket/Umbrella/Platform Master Protocols evaluate the same or related interventions across multiple cohorts: ① **Per-cohort hypothesis independence**: By default each tumor type/cohort is an **independent hypothesis**, each controlling its own family-wise error rate (FWER) — i.e., each cohort's α is typically allocated by **Bonferroni or a hierarchical strategy** (e.g., K cohorts each α/K), not sharing total α; shared error rate applies only under specific presets (e.g., common control, unified sample-size re-estimation) and must be declared in advance; ② **Multiplicity control**: Prespecify each cohort's α in the SAP, whether a primary/exploratory cohort is set, whether multiplicity borrowing is allowed; ③ **Approval interpretation**: If only 2 cohorts show effect and the rest are negative, FDA/NMPA typically **approve the corresponding indication based only on the supportive evidence of the effective cohorts** — negative cohorts do not "drag down" positive cohorts, but the applicant must explain overall safety and cross-cohort consistency (class effect), and whether negativity is due to insufficient power or biological heterogeneity; ④ Single-arm basket (e.g., rare mutation) must combine §3.8 external control and conditional-approval logic. Cohort division, α allocation and approval strategy are dynamic items — follow FDA/NMPA Master Protocol guidance and current review logic (officially verify).

### 5.10 Patient-reported outcome (PRO / ePRO) as primary endpoint — validation & acceptability (workflow C / registration)
Using a patient-reported outcome (PRO, collected via ePRO) as a **supportive primary endpoint for approval** (e.g., symptom NRS score) must satisfy regulatory validation and acceptability: ① **Endpoint validation (qualification)**: The PRO instrument must have **content validity, reliability, interpretability (anchor-based MCID)**, preferably via the FDA/EMA PRO instrument validation framework or equivalent evidence; the ePRO system must be validated (interface, computation, offline, data completeness); ② **ALCOA+ and blinding**: Daily ePRO self-report has ALCOA+ advantages (timestamp, tamper-proof), but **lacks independent blinded verification** — if the endpoint is subjective and unblinded, strengthen blinding design (e.g., blinded endpoint adjudication committee BEC, centralized assessment, assessor blinding) to control measurement bias; ③ **Regulatory acceptability**: FDA/NMPA are cautious about "using patient self-reported symptoms as primary endpoint" — must prove the symptom's clinical importance, that the instrument detects real change, and that it is not merely avoiding hard endpoints; accompanying objective endpoints (e.g., exercise tolerance, objective physiological indicators) strengthen persuasiveness; ④ Missing and re-collection must follow §4.4 (CDISC/CSR transparency). PRO-as-primary-endpoint validation standards and acceptability are dynamic items — follow FDA PRO guidance/EMA and current NMPA requirements (officially verify).

### 5.11 Pharmacoeconomics (HEOR) & access evidence: EQ-5D, utility mapping & QALY (workflow registration / access) — trial-collected PRO/cost data supporting payer access
- **Scenario / Role**: HEOR / Regulatory Affairs — a pivotal trial concurrently collects health-related quality of life (HRQoL, e.g., EQ-5D-5L) and medical-resource/cost data intended for payer access and pricing; must explain utility values and QALY handling.
- **Correct handling path**: ① **Utility mapping**: When a preference-based utility instrument is not used directly (e.g., SF-36), use a validated mapping function to convert to EQ-5D utility, noting the mapping model and uncertainty; ② **QALY calculation**: Based on utility × survival time; missing/censored HRQoL imputed by a predefined method (echoing `ref-ops-data.md` §4.4 missing-data handling); clarify time preference and discounting; ③ **Within-trial EE (economic evaluation) design**: Prespecify perspective (health system/society), cost items, discount rate, sensitivity analysis (deterministic/probabilistic); avoid post-hoc patchwork; ④ **Relation to regulator**: HRQoL/PRO as endpoint must satisfy §5.10 validation and acceptability; economic evidence supports **access/pricing**, not the registration efficacy conclusion; ⑤ **Data source**: Real-world cost can link to RWE (§3.8), but distinguish "registration evidence" from "access evidence" use.
- **Key points**: QALY/utility is access evidence, not registration efficacy evidence; mapping method and missing-data handling must be preset and subjected to uncertainty analysis.
- ⚠️ EQ-5D version, discount rate, QALY threshold and payer-access standards are dynamic items — follow each country's HTA/payer and current NMPA requirements (officially verify).

### 5.12 Orphan-drug designation & natural-history-study external control (workflow registration) — rare-disease trial-waiver path
- **Scenario / Role**: Rare-disease expert / Regulatory Affairs — a rare-disease drug applies for orphan-drug designation and uses a natural-history study as external control to support conditional approval.
- **Correct handling path**: ① **Orphan designation**: File designation per jurisdiction (prevalence threshold, severity, no satisfactory therapy); upon designation enjoys tax/review incentives; ② **Natural-history external control**: When rare disease lacks a concurrent control, use prospective/retrospective natural-history studies to build an external control (echoing `ref-ops-gcp-site.md` §3.8 external control 5 points + RWE); must preset comparable population, covariates, time trend and bias control; ③ **Waiver path**: Orphan drug + single-arm + natural-history control is commonly used for conditional approval, but requires Pre-IND pre-acceptance (§3.8); ④ Natural-history data quality (completeness/representativeness) must meet evidence standards, avoid "cobbling together a control".
- **Key points**: Orphan designation is an eligibility incentive, not evidence substitution; natural-history external control must equally satisfy prespecification and bias control.
- ⚠️ Orphan-drug prevalence threshold, designation procedure and incentives, and natural-history-data acceptability are dynamic items — follow current FDA ODA/EMA/NMPA rare-disease and orphan-drug regulations (officially verify).

### 5.13 Vaccine / biologic bridging & immunogenicity comparability (workflow registration) — expanding indication or population
- **Scenario / Role**: Regulatory Affairs / Clinical Pharmacology — an approved vaccine/biologic intends to expand population (e.g., age, region) or change process; bridging trial needed to prove immunogenicity comparability.
- **Correct handling path**: ① **Bridging logic**: Use immunogenicity (geometric mean titer GMT, seroconversion rate) as the primary bridging endpoint to prove **comparability (bridging)** of the new population/process vs the originally approved population; ② **Design**: Typically non-inferior to original-population immunogenicity, preset comparability margin (e.g., 95% CI lower bound of GMT ratio > a proportion); ③ **Safety**: Local/systemic adverse-reaction profile of the new population/process must be comparable and non-inferior; ④ **Process change**: Follow a tiered comparability study (analytical + non-clinical + clinical immunogenicity); major changes may require new confirmation; ⑤ Communicate bridging margin and acceptance criteria with the regulator in advance.
- **Key points**: Vaccine bridging centers on immunogenicity comparability; margin must be preset; process change must follow tiered comparability evidence.
- ⚠️ Bridging margin, seroconversion determination and process-change comparability requirements are dynamic items — follow current FDA/EMA/NMPA vaccine and biologic bridging guidelines (officially verify).

### 5.14 Independent imaging (BICR) charter & discrepancy handling (workflow C / registration) — imaging endpoint read governance
- **Scenario / Role**: Independent imaging (BICR) / Statistics — set the BICR charter, handle BICR vs investigator-assessment discrepancies, imaging QC and bias control.
- **Correct handling path**: ① **BICR charter**: Preset assessment standard (RECIST/iRECIST version), blinding, independent reader qualification, arbitration mechanism, QA and re-read rules; ② **Discrepancy handling**: When BICR and investigator assessment disagree, follow the **preset primary assessor (typically BICR)**; discrepancy rate used as sensitivity analysis; do not arbitrarily use "the side favorable to the result"; ③ **Imaging QC**: Unified imaging-acquisition protocol, complete transmission, centralized review, re-read agreement (Kappa/ICC); ④ Link with SAP: Imaging-endpoint determination rules, missing/non-evaluable handling clearly stated; ⑤ AI-assisted read must satisfy §5.6 non-inferiority-to-BICR validation.
- **Key points**: BICR's essence is blinding and independence — charter preset, discrepancies adjudicated per preset, avoid selective adoption.
- ⚠️ BICR charter elements, discrepancy handling and imaging-QC requirements are dynamic items — follow current FDA/CDE imaging-endpoint guidelines (officially verify).

### 5.15 Platform trial MAMS & flagging rules (workflow B / C) — multi-arm multi-stage & arm exit
- **Scenario / Role**: Biostatistician / Regulatory — a platform trial uses MAMS (multi-arm multi-stage); how to "flag" (stop) an ineffective arm and control error rate.
- **Correct handling path**: ① **MAMS structure**: Multiple experimental arms share a control and are evaluated in stages (interim); an ineffective arm is "flagged" — enrollment stopped but other arms unaffected; ② **Error-rate control**: Flagging requires preset α-spending (e.g., alpha-spending or false discovery rate FDR); with shared control the overall family-wise error rate is controlled (echoing §5.9 multiplicity); ③ **Flagging rule**: Based on interim efficacy/safety boundary, preset flag-and-continue criteria, executed transparently; ④ **Shared control arm**: Shared control improves efficiency but control integrity must be maintained; ⑤ **Regulatory acceptance**: Platform-trial design requires Pre-IND communication; the interpretability of flagging decisions is key to approval (§5.9 approval by positive cohort).
- **Key points**: Platform-trial efficiency comes from shared control and staged evaluation; flagging must be preset and error-rate controlled, otherwise cross-arm inference is distorted.
- ⚠️ MAMS α control, flagging boundary and platform-trial acceptability are dynamic items — follow current FDA/EMA/NMPA Master Protocol guidelines (officially verify).

# Methods & Product Topics (workflow C/registration · 5.16-5.25)


### 5.16 Reliability & boundaries of RWE for label expansion (workflow registration / RWE)
- **Scenario / Role**: Medical Affairs / Regulatory — use real-world evidence (RWE) to support a new indication/population label expansion for an approved drug; must argue reliability.
- **Correct handling path**: ① **Evidence level**: RWE for label expansion is lower than RCT; requires a preset protocol (target-trial emulation, §3.8) + bias control (PS/instrumental variable/negative control); ② **Applicable boundary**: Considered only when RCT is infeasible or as supportive evidence; major efficacy claims still rely mainly on RCT; ③ **Data quality**: RWD source (registry/payer/EMR) must meet applicability (§3.8 RWE methods); ④ **Regulatory communication**: The RWE path for label expansion requires Pre-IND/Type B pre-acceptance; ⑤ Link with §5.12 natural history, §3.8 external control — RWE label expansion is one of its applications.
- **Key points**: RWE can support label expansion but not replace RCT confirmation — must be preset-designed, bias-controllable, regulator-accepted.
- ⚠️ RWE label-expansion acceptability and data requirements are dynamic items — follow current FDA/EMA/NMPA RWE and labeling guidelines (officially verify).

### 5.17 Clinical endpoint adjudication committee (CEC / EAC) (workflow C / registration) — blinded adjudication of clinical events
- **Scenario / Role**: Independent imaging / Statistics — set a clinical endpoint adjudication committee (CEC/EAC) for blinded adjudication of clinical events (MI/stroke/death), distinct from BICR (imaging).
- **Correct handling path**: ① **CEC duties**: Blindly adjudicate occurrence, time and nature of clinical composite-endpoint events (e.g., cardiovascular events) per preset standards, reducing measurement bias; ② **Distinction from BICR**: BICR handles imaging endpoints (§5.14), CEC handles clinical events; the two can run in parallel; ③ **Charter**: Preset adjudication standards, blinding, arbitration, QA; adjudicators independent of sponsor/investigator; ④ Link with SAP: Event definition, missing/non-adjudicable handling clearly stated; ⑤ Adjudication discrepancy rate used as sensitivity analysis.
- **Key points**: CEC's essence is blinded independent adjudication of clinical events — charter preset, independent execution, avoid investigator bias.
- ⚠️ CEC charter elements and event-adjudication requirements are dynamic items — follow current FDA/CDE endpoint-adjudication guidelines (officially verify).

### 5.18 Biosimilar clinical bridge & comparability boundary (workflow C / registration) — tiered evidence of analytical / PD / clinical
- **Scenario / Role**: Regulatory Affairs / Clinical Pharmacology — when a biosimilar shows high analytical + PD similarity, whether some clinical trials can be waived (clinical bridge/streamlined clinical) and where the boundary lies.
- **Correct handling path**: ① **Tiered comparability**: Analytical similarity (structure/function) → PK/PD similarity → clinical similarity, evidence accumulates bottom-up (echoing §5.7 overall evidence chain); ② **Clinical-waiver boundary**: When analytical + PD are sufficiently similar and MOA/immunogenicity support it, confirmatory clinical trials can be streamlined or waived ("streamlined clinical" path), but requires prior regulatory acceptance; ③ **Residual uncertainty**: If evidence in some dimension is insufficient, supplement with clinical (e.g., efficacy confirmation or immunogenicity bridging, §5.7); ④ **Regulatory communication**: Comparability evidence and waiver scope require Pre-IND/Type B acceptance.
- **Key points**: Biosimilar clinical waiver is not "waive all" — tied to the analytical/PD similarity tier; boundary requires regulatory acceptance.
- ⚠️ Biosimilar clinical-waiver boundary and comparability requirements are dynamic items — follow current FDA/EMA/NMPA biosimilar technical guidance (officially verify).

### 5.19 Quantitative assessment of racial factor (RFE) & bridging argument (workflow registration / A) — quantification of ICH E5 extrapolation
- **Scenario / Role**: Regulatory Affairs / Clinical Pharmacology — in US-China dual filing, go beyond qualitative ethnic sensitivity to quantitatively assess the racial factor (RFE = (μ_E - μ_A) / σ) and the need for extrapolation.
- **Correct handling path**: ① **RFE quantification**: Quantify the racial factor via population PK/PD differences (RFE = exposure/effect mean difference / standard deviation), assess whether it exceeds a preset threshold requiring bridging; ② **Bridging argument**: Small RFE with narrow CIs → extrapolable; large or uncertain RFE → requires China data/bridging trial (echoing §5.5 ethnic sensitivity); ③ **Covariates**: Body weight, metabolic-enzyme frequency, medical practice etc. as RFE explanatory variables; ④ **Regulatory communication**: Quantitative ethnic analysis requires Pre-IND/Type B acceptance; MRCT China-proportion argument (§5.5) links with it; ⑤ Complements §5.16 RWE, §3.8 external control.
- **Key points**: Ethnic bridging moves from "qualitative E5" to "quantitative RFE" — threshold must be preset and accepted by both regulators.
- ⚠️ RFE threshold and bridging-quantification requirements are dynamic items — follow ICH E5 and current China/NMPA, FDA ethnic-bridging guidelines (officially verify).

### 5.20 Bioequivalence (BE) trial design & determination (workflow C / registration) — demonstrating therapeutic equivalence via BA/BE
- **Scenario / Role**: Clinical Pharmacology / Regulatory — generics/formulation changes use a BE trial to prove bioequivalence to the reference product; must satisfy design (fasting/fed) and determination standards (echoing clinical §1.5 BA/BE).
- **Correct handling path**: ① **Design**: Crossover design (common 2×2), subject number, fasting/fed, sampling time points, washout must meet power; ② **Determination**: BE determined by geometric mean ratio (GMR) of AUC/Cmax and its 90% CI falling within the preset equivalence margin (commonly 80.00%–125.00%); ③ **Highly variable drug (HVDP)**: Consider scaled average bioequivalence (SABE) or replicate design, preset method; ④ **Narrow therapeutic index (NTID)**: Apply stricter determination; ⑤ **Distinction from §5.7**: BE is for chemical generics/formulation changes; similarity is for biosimilars — different evidence tiers; ⑥ **Registration**: BE results support generic/consistency-evaluation filing.
- **Key points**: BE is determined by PK endpoint + preset equivalence margin; margin and HVDP/NTID handling must be preset; different path from biosimilar "similarity".
- ⚠️ BE equivalence margin, HVDP/NTID handling and sample-size requirements are dynamic items — follow current NMPA/FDA/EMA BE and bioequivalence technical guidance (officially verify).

### 5.21 Compassionate use & expanded access (workflow registration / A) — compliant path to access investigational drugs outside trials
- **Scenario / Role**: Medical Affairs / Regulatory — a critical patient with no standard therapy and ineligible per entry criteria applies to use an investigational drug (compassionate use/expanded access/named patient); must follow a compliant path.
- **Correct handling path**: ① **Path types**: Per jurisdiction there are compassionate use, expanded access (individual/intermediate/treatment IND), named patient and other procedures; ② **Preconditions**: Typically the trial must have shown some safety, the patient has no alternative therapy, ethics and regulatory approval, and sponsor agrees to supply; ③ **Responsibility & monitoring**: Compassionate use still requires safety monitoring and reporting (SUSAR/AE still enter the safety-information stream), must not replace RCT evidence; ④ **Informed consent**: Separate informed consent (not trial ICF), clarifying investigational nature, risks and voluntariness; ⑤ **Relation to registration**: Compassionate-use data generally do not serve as primary marketing evidence but can enter the safety database (§4.4 DSUR); ⑥ **Multi-country differences**: Procedures, access and reimbursement differ by jurisdiction; must comply separately.
- **Key points**: Compassionate use is a "humanitarian exception" not a marketing channel — requires compliant approval + ongoing safety monitoring, and does not constitute efficacy evidence.
- ⚠️ Compassionate-use/expanded-access procedures, approval conditions and reporting requirements are dynamic items — follow FDA expanded access, EMA compassionate use and current NMPA regulations (officially verify).

### 5.22 Pediatric investigation plan (PIP) & pediatric-indication regulatory path (workflow registration) — mandatory planning of pediatric development
- **Scenario / Role**: Regulatory Affairs / Pediatric expert — a new drug must file a pediatric investigation plan (PIP) per jurisdiction (e.g., EU Pediatric Regulation) or pursue pediatric-indication development, obtaining pediatric exclusivity/incentives.
- **Correct handling path**: ① **PIP content**: Pediatric applicability assessment, study planning (dose §1.7, age stratification, safety), timeline and waiver/deferral; ② **Regulatory interaction**: PIP requires regulatory approval (e.g., EMA PDCO), coordinated with the adult development plan; ③ **Incentives**: Pediatric exclusivity/priority review etc.; ④ Linkage: With §1.7 pediatric dose/Assent, §3.5.1 pediatric consent; ⑤ **China**: Pediatric drug-development technical guidance and suitable formulation/palatability requirements.
- **Key points**: Pediatric development is "mandatory planning + regulatory approval" — PIP coordinated with the adult plan; dose and consent must be pediatric-specific.
- ⚠️ PIP requirements, pediatric incentives and formulation/palatability requirements are dynamic items — follow EMA Pediatric Regulation and NMPA pediatric-drug guidance (officially verify).

### 5.23 Statistical analysis report (SAR) & its relation to CSR / TFL (workflow C / G) — independent delivery at the analysis layer
- **Scenario / Role**: Statistics / Medical writing — after database lock, issue a statistical analysis report (SAR) as the statistical support for the CSR; must be independent, complete, traceable.
- **Correct handling path**: ① **SAR content**: Analysis-set definitions, baseline, primary/secondary/subgroup/sensitivity analyses, intercurrent events (§4.4), estimand (§3.1) implementation, consistent with SAP; ② **Relation to CSR**: SAR is the basis for the CSR statistical section; the CSR does not repeat all details but must cite and be consistent (§5.1); ③ **Independent QC**: Statistical analysis and programming (§4.5 TFL) require independent QC; SAR reviewed by statistics and medical; ④ Linkage: With §4.4 missing/CDISC, §4.5 programming — data version locked; ⑤ **Transparency**: SAR must disclose all analyses (preset/exploratory) and deviations.
- **Key points**: SAR is "independent delivery at the analysis layer" — consistent with CSR but not duplicative; independent QC and transparent disclosure are regulatory-inspection focuses.
- ⚠️ SAR content, consistency with CSR and disclosure requirements are dynamic items — follow current statistical standards and regulatory-submission requirements (officially verify).

### 5.24 Clinical outcome assessment (COA) & endpoint selection (workflow C / G) — unvalidated tools struggle to support key endpoints
- **Scenario / Role**: Statistics / Clinical endpoint — selecting a clinical outcome assessment tool (COA: clinician-/observer-/patient-/performance-reported) as an efficacy/safety endpoint must ensure reliability and validity.
- **Correct handling path**: ① **COA types**: PRO/ePRO (§4.10), ObsRO, ClinRO, PerfRO have different applicable scenarios; ② **Reliability & validity**: The tool must be validated (reliability/validity/responsiveness); cross-culturally requires linguistic validation (§4.14); ③ **Endpoint tier**: Place the COA within the estimand (§3.1) framework, clarifying primary/secondary; ④ **Bias control**: Blinded assessment, avoid interrogation bias; ⑤ **With regulator**: Key endpoints require prior regulatory confirmation of acceptability (§8.11).
- **Key points**: COA selection is "tool validation + tier positioning + bias control" — endpoints supported by unvalidated tools are hard to accept.
- ⚠️ COA types, validation requirements and endpoint acceptability are dynamic items — follow FDA COA/PRO guidance and current ICH standards (officially verify).

### 5.25 Genotoxicity & carcinogenicity non-clinical safety evidence (workflow C / non-clinical) — non-clinical safety base
- **Scenario / Role**: Non-clinical / Regulatory — a drug must provide genotoxicity (mutagenic) and carcinogenicity (long-term) non-clinical evidence to support the clinical safety window and labeling.
- **Correct handling path**: ① **Genotoxicity**: Standard battery (bacterial reverse-mutation Ames + in vitro chromosomal aberration/micronucleus + in vivo micronucleus), per ICH S2; ② **Carcinogenicity**: Routine 2-year rodent or transgenic/short-term model, per exposure duration and indication (long-term use requires carcinogenicity); ③ **Photo-carcinogenicity**: Photoreactive substances add photo-carcinogenicity assessment (§1.14); ④ **With dose**: Safety window derived from NOAEL/exposure ratio (§1.5 FIH); ⑤ **With clinical**: Positive genotoxicity requires linked clinical-monitoring strategy (§5.3).
- **Key points**: Genotoxicity/carcinogenicity is the "non-clinical safety base" — standard battery + exposure-driven carcinogenicity strategy supports clinical risk communication.
- ⚠️ Genotoxicity battery, carcinogenicity study strategy and determination are dynamic items — follow ICH S1/S2 and current regulatory non-clinical-safety guidelines (officially verify).
